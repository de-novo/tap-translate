# Tap Translate 기획서

| 항목 | 내용 |
| --- | --- |
| 제품 | Tap Translate / 탭 번역 |
| 버전 기준 | 2.0.0 (Chrome MV3) |
| 문서 성격 | 제품 기획. 구현 스펙이 아님 |
| 작성일 | 2026-03-24 |
| 상태 | 초안. 지금은 작성자 1인 사용 |

## 한 줄

페이지 위에 떠 있는 칩을 한 번 눌러, 지금 보고 있는 글을 목표 언어로 바꾼다.

우클릭 메뉴나 Chrome 번역 막대를 대신하는 런처가 아니다. 페이지 글을 그 자리에서 바꾸는 번역기다.

## 왜 만드는가

영어·기타 언어 페이지를 자주 보는 사람이 Chrome 기본 번역을 쓰기엔 단계가 많다. 우클릭 → 번역, 주소창 번역 아이콘, 사이트마다 다른 동작. 보고 있는 글을 바로 바꾸고 싶을 뿐인데 경로가 길다.

비슷한 제품은 이미 있다. 구글 번역 확장, Immersive Translate, Mate. 그들 대부분은 페이지·선택·자막·PDF·사전을 한 제품에 넣는다. Tap Translate는 그 반대다. **탭 한 번**이 깨지지 않는 범위만 맡는다.

서버를 두지 않고, 계정 없이, 오픈소스(MIT)로 유지한다. 번역 요청은 확장 서비스 워커에서 Google 공개 웹 번역 엔드포인트로 간다. 1st-party API 키가 없다.

## 원칙

1. **한 번의 탭으로 끝나야 한다.** 설정 화면을 열어야 번역되는 기능은 넣지 않는다.
2. **페이지를 떠나지 않는다.** 새 탭의 Google 번역 페이지는 실패 시에만 연다.
3. **서버와 계정이 없다.** 설정은 `chrome.storage.sync`에만 둔다. 키 이름은 1.x와 호환한다 (`targetLang`, `alwaysTranslate`, `hiddenHosts`, `position`, `showFab`).
4. **Chrome만 한다.** 아이폰 오버레이·사파리·Firefox는 범위 밖이다.
5. **페이지 번역의 품질을 먼저 지킨다.** 새 기능이 칩 드래그, 뷰포트 우선 번역, 원문 복원을 깨면 넣지 않는다.
6. **유료화하지 않는다.** 비공식 gtx 경로를 쓰는 이상, 스토어 유료 판매는 리스크만 키운다. 기부·후원은 열어둘 수 있다.

## 지금 있는 것 (2.0)

| 기능 | 동작 |
| --- | --- |
| 플로팅 칩 | 페이지 위 Shadow DOM 칩. 드래그로 위치 저장 |
| 페이지 번역 | 뷰포트 글 먼저, 나머지는 병렬 배치. 목표 언어면 건너뜀 |
| 원문 | 같은 칩에서 되돌림 |
| 목표 언어 | 칩·팝업에서 선택. 캐시는 언어별로 분리 |
| 항상 번역 | 외국어 페이지를 열면 자동 번역 |
| 이 사이트에서 숨기기 | 칩만 숨김. 단축키는 남음 |
| 단축키 | `Alt+Shift+T` / `⌥⇧T` 로 번역·원문 전환 |
| 실패 처리 | 확장 컨텍스트 무효화, 미지원, 실패. Google 번역 페이지로 탈출 가능 |
| 입력 번역 | 기본 꺼짐. 입력 목표 언어는 페이지와 별개. 칸 아래 미리보기 + 복사. 원문은 덮지 않음 |
| 이미지 번역 | 기본 꺼짐. 文을 열면 [원본][번역본]. 가로로 꽉 찬 그림은 아래에 번역본. 상세는 [image-translate.md](image-translate.md) |

백엔드: Google gtx가 기본. 기기 내 Translator API는 폴백이지만, 모델이 없는 브라우저(ego 등)에서는 쓰이지 않는다.

없는 것: 선택 번역, 사이트별 항상/절대, 우클릭 메뉴, 자막, PDF, 사전, 기록.

## 누구의 어떤 일

지금은 스토어·다인 사용자가 아니다. **작성자 한 사람**이 영어 문서, 위키, 이슈, 뉴스를 읽는 손이 기준이다. 일반화는 미룬다.

칩 상호작용은 [ux-chip.md](ux-chip.md)가 우선한다. 입력 번역은 [input-translate.md](input-translate.md)가 우선한다. 선택 번역·사이트 규칙·입력 번역은 그 칩이 편해진 다음에 붙인다.

| Job | 지금 | 빈 칸 |
| --- | --- | --- |
| 이 페이지를 통째로 읽고 싶다 | 칩 탭 | — |
| 이 문단만 확인하고 싶다 | 없음. 페이지 전체를 바꾸거나 포기 | 선택 번역 |
| 이 사이트는 항상 / 절대 번역 | 전역 항상 번역, 또는 칩 숨김 | 사이트 규칙 |
| 내가 쓴 글을 다른 언어로 확인하고 싶다 | 칸 아래 미리보기 + 복사 | — |
| 자막·PDF·단어 뜻을 보고 싶다 | 없음 | 하지 않음 (아래 비범위) |

## 넣지 않는 것

지금 로드맵에 올리지 않는다. 수요가 있어도 제품이 바뀐다.

- YouTube·넷플릭스 자막
- PDF, 로컬 파일, `file://`
- 단어 호버 사전
- 원문과 번역을 문장 단위로 나란히 보기
- 번역 기록, 클라우드 동기화, 계정
- 용어집, 커스텀 엔진 UI, 유료 모델 키 입력
- Firefox / Safari / iOS 오버레이
- Chrome 네이티브 번역 막대 호출 (공개 API 없음)

나란히 보기와 자막은 나중에 재검토할 수 있다. 선택·사이트·입력이 안정된 다음이다.

## 다음에 넣을 기능

우선순위는 “탭 한 번”을 얼마나 자주, 덜 귀찮게 만드는가다.

### P0. 선택한 문장만 번역

페이지를 통째로 바꾸고 싶지 않은 순간이 가장 많다. 문서, 위키, 긴 스레드.

- 텍스트를 드래그하면 작은 칩이 선택 근처에 뜬다.
- 탭하면 그 문장만 번역해 보여 준다. 기본은 팝업. 원문 치환은 선택 사항으로 둔다.
- 칩을 탭하는 기존 페이지 번역과 같은 백엔드, 같은 목표 언어를 쓴다.
- 우클릭 메뉴는 넣지 않거나, 나중에 보조로만 넣는다. 시작점이 우클릭 불편이었기 때문이다.

성공: 선택 후 1초 안에 번역이 보이고, 페이지 번역 칩과 위치가 겹쳐 싸우지 않는다.

### P1. 사이트별 항상 / 절대

지금은 전역 “다른 언어 항상 번역”과 “이 사이트에서 버튼 숨기기”만 있다. Chrome 번역이 주는 습관이 없다.

- `이 사이트는 항상 번역`
- `이 사이트는 번역하지 않음` (칩은 남을 수 있음)
- 칩 숨김과 번역 거부는 분리한다. 숨김은 UI, 거부는 동작.
- 저장은 기존 `alwaysTranslate` / `hiddenHosts`를 확장하되, 1.x 값이 깨지지 않게 한다.

성공: 자주 가는 영어 문서는 열자마자 번역되고, 이미 한국어인 사이트는 손대지 않는다.

### P2. 입력 번역

읽는 번역의 짝. 트위터·레딧을 한국어로 보고, 내가 쓴 글은 영어로 확인하고 싶다. 상세는 [input-translate.md](input-translate.md).

- 페이지 목표 언어와 **입력 목표 언어를 나눈다.** 예: 페이지 한국어, 입력 영어.
- 포커스된 검색창·글쓰기 칸 **아래**에 번역이 뜬다. 칸의 원문은 덮지 않는다.
- 본동작은 복사다. 칸에 바꿔 넣는 치환은 넣지 않는다.
- 비밀번호, 코드 미러, 터미널 같은 칸은 제외한다.

성공: 한글을 칸에 남긴 채 영어 미리보기를 보고, 한 번에 복사한다. 페이지 칩은 그대로다.

## 단계

| 단계 | 범위 | 출시 기준 |
| --- | --- | --- |
| 지금 (2.0) | 페이지 번역 + 드래그 칩 | ego / Chrome에서 칩 이동·번역·원문 |
| 다음 (2.1) | P0 선택 번역 | 선택 → 팝업 번역. 페이지 번역 회귀 없음 |
| 그다음 (2.2) | P1 사이트 규칙 | 항상/절대가 팝업·칩 메뉴에 보임 |
| 여유 (2.3) | P2 입력 번역 | 트위터·레딧 입력칸 아래 미리보기 + 복사 |
| 보류 | 나란히 보기, 자막, PDF | 위 단계가 쓰인 뒤에만 다시 논의 |

Chrome Web Store 제출은 별도 결정이다. 지금은 오픈소스 저장소와 로컬/언팩 사용이 기본이다.

## 성공을 어떻게 볼 것인가

1st-party 서버가 없으므로 원격 분석은 넣지 않는다. 판단은 사용 장면으로 한다.

- 처음 쓰는 사람이 설명 없이 칩을 눌러 페이지를 번역한다.
- 칩을 원하는 곳으로 옮기고, 새로고침 뒤에도 그 자리에 있다.
- 긴 글에서 문장만 확인하고 싶을 때 페이지 전체를 바꾸지 않아도 된다. (2.1)
- 자주 가는 사이트에서 칩을 매 방문마다 누르지 않아도 된다. (2.2)
- 페이지는 한국어로 읽으면서, 내가 쓴 한글의 영어를 칸 아래에서 복사한다. (2.3)

정량 지표를 나중에 넣더라도, 번역문 내용은 보내지 않는다.

## 열린 질문

구현 전에 정하면 좋은 것들이다. 지금은 초안 가정이 있다.

1. **선택 번역의 기본 동작**  
   가정: 팝업으로 보여 주고, 원문 치환은 하지 않는다. 페이지를 조용히 바꾸면 긴 글에서 위치를 잃기 쉽다.

2. **사이트 규칙 저장 형태**  
   가정: `alwaysTranslate`에 호스트를 추가하는 쪽으로 확장하고, `"*"` 전역 플래그는 유지한다. 1.x 설정이 리셋되면 안 된다.

3. **입력 번역 UI**  
   가정은 [input-translate.md](input-translate.md)로 옮겼다. 칸을 치환하지 않고 아래에 미리보기를 붙인다. 페이지 칩과 설정을 나눈다.

4. **스토어 배포 시점**  
   가정: 2.1(선택 번역)까지 쓴 뒤 검토한다. 페이지 번역만으로도 제출할 수는 있다.
