# 이미지 번역

| 항목 | 내용 |
| --- | --- |
| 제품 | Tap Translate / 탭 번역 |
| 대상 | 작성자 1인. 지금 쓰는 사람은 나뿐이다 |
| 문서 성격 | 제품 기획. 구현 스펙이 아님 |
| 작성일 | 2026-09-06 |
| 상태 | 1차 구현. `文`을 열면 [원본][번역본]. 가로로 꽉 찬 그림은 아래 |

관련: [기획서](planning.md), [칩 UX](ux-chip.md)

## 한 줄

원본 그림은 손대지 않는다. `文`을 누르면 **같은 그림의 번역본**이 원본 옆에 붙는다. 공간이 없으면 아래에 붙는다.

```
[ 원본 사진 ] [ 번역된 사진 ]
```

## 왜 이 쪽인가

도식·카톡·영수증의 정보는 글자만이 아니다. 칸의 자리와 화살표다.

카드는 제목만 세로로 쌓아서 흐름을 버린다. 원본 위에 번역을 얹으면 자리는 지키지만, 내가 보던 그림을 가린다. 이미 한 번 방해라고 버렸다.

[원본][번역본]은 둘을 나눈다. 원본은 그대로 두고, 번역본이 같은 배치로 한글을 맡는다. 화살표를 따라가는 일은 번역본에서 한다.

## 지금 무엇이 부족한가

GROK BOT 흐름도에서 `文`을 열면 지금 옆에 카드가 뜬다.

```
OBJECTIVE → CHIEF OF STAFF → RESEARCH / BUILD / REVIEW → GROK 4.6 → APPROVAL → RESULT
```

카드는 이렇게 된다.

```
봇 그로크
잠들지 않는 알 팀
연구봇
```

제목은 옮겼다. 흐름은 사라졌다. 옆 본문도 밟는다.

이미 버린 것:

| 시도 | 왜 버렸나 |
| --- | --- |
| 페이지 번역과 같이 그림 위에 자동 덮개 | 읽는 그림을 가림 |
| 이미지 옆 카드 | 옆 글을 가림. 그림의 공간을 버림 |
| `文` + 카드 | 글은 안 가리지만 그림 정보는 목록 |
| `文` + 원본 칸 위에 얹기 | 자리는 지키지만 원본을 다시 가림. 덮개와 같은 종류 |

## 누구의 어떤 일

| Job | 지금 | 이 기능 |
| --- | --- | --- |
| 영어 본문을 한글로 읽는다 | 칩 | 그대로 |
| 이 도식이 무슨 칸인지 따라가고 싶다 | `文` → 카드 | `文` → 원본 옆(또는 아래)에 같은 배치의 번역본 |
| 원본 그림을 가리지 않고 싶다 | 원본 위에 얹거나 카드 | 원본은 그대로. 번역은 복제본 |

첫 장면은 트윗 속 도식과 카톡 캡처다.

## 원칙

1. **원본은 덮지 않는다.** 내가 보던 사진은 그대로다.
2. **번역본은 같은 그림이다.** 칸과 화살표가 같은 자리에 있어야 그 그림을 번역한 것이다. 목록이 아니다.
3. **자동으로 붙이지 않는다.** `文`을 연 그 장만. 칩의 접힌 본체와 같다.
4. **트윗 자리를 반으로 쪼개 원본을 작게 만들지 않는다.** 그림이 이미 가로로 꽉 찼으면 번역본은 **아래**다. 옆에 둘 여유가 있을 때만 좌우.
5. **페이지 DOM의 원본 `img`는 바꾸지 않는다.** 번역본은 우리 레이어다. `文`을 끄거나 페이지 원문으로 되돌리면 사라진다.

## 장면

페이지는 한국어, 이미지도 번역은 켜짐.

도식 트윗을 연다. 본문은 한글이다. 그림은 영어 그대로, 모서리에 `文`만 있다.

`文`을 누른다. 트윗 그림은 그대로다. 그 **아래**(트윗처럼 가로로 꽉 찬 그림)에 같은 크기의 번역본이 붙는다. OBJECTIVE 칸에 한글이 있고, 화살표는 그 칸을 가리킨다.

옆에 여백이 있는 문서 나란히 보기에서는 원본 오른쪽에 번역본이 붙는다.

다시 `文`을 누르면 번역본만 사라진다.

## UI

| 상태 | 보이는 것 |
| --- | --- |
| 이미지도 번역 꺼짐 | 표시 없음 |
| 켜짐, 인식 중 | 모서리 `文`이 흐림 |
| 켜짐, 글 없음 | 표시가 사라짐 |
| 켜짐, 준비됨 | 모서리 `文` |
| `文` 열림, 옆에 자리 있음 | `[원본][번역본]` |
| `文` 열림, 그림이 가로로 꽉 참 | 원본 그대로, **아래에** 번역본 |
| `文` 닫힘 / 원문 | 번역본 없음 |

한 번에 한 장만 연다.

번역본은 원본을 복사한 뒤, OCR이 잡은 칸에만 한글을 그린 그림이다. 화살표·아이콘·사진은 복사된 채 남는다.

자리를 고르는 규칙은 한 곳에 둔다. 화면이 다시 세지 않는다. 옆에 최소 너비가 되면 오른쪽, 아니면 아래.

## 넣지 않는 것

- 옆 카드, 아래 목록, 번호+범례
- 원본 `img` 위에 직접 덮개
- 원본을 반으로 줄여 옆에 번역본을 끼워 넣기
- 새 탭, 전체 화면 라이트박스
- 모든 그림에 자동으로 번역본 붙이기
- 번역본을 파일로 저장하기

라이트박스는 페이지를 떠난다. 원본을 줄이면 작은 칸을 더 못 읽는다.

## 성공을 어떻게 볼 것인가

- `文`을 열기 전에도, 연 뒤에도, 트윗 속 원본 도식은 같은 크기다.
- 번역본에서 화살표를 따라가며 각 칸의 한글을 읽는다. 목록을 스크롤하지 않는다.
- 카톡 캡처의 번역본은 말풍선 자리에 번역이 있다.
- `文`을 끄면 번역본만 사라지고 원본은 그대로다.
- 페이지 칩의 탭·드래그·원문 복원이 같다.

| 번역 품질 (AI → 알) | 표면이 아님. 엔진·OCR. 이번 기획에서 풀지 않음 |

## 열린 질문

1. **아래 번역본이 다음 트윗을 얼마나 가려도 되나**  
   가정: 원본과 같은 크기면 길다. 그래도 원본을 줄이지 않는다. 가리는 건 `文`을 연 동안만이다.

2. **아주 작은 라벨** (`TOOLS`, `STATE`)  
   가정: 번역본 칸 안에 맞춘다. 1차 성공 조건이 아니다.

3. **우선순위**  
   가정: 칩이 접힌 본체라는 조건은 유지한다. 이 일은 그림 한 장을 원본과 번역본으로 나누어 읽는 손이다.
