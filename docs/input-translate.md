# 입력 번역

| 항목 | 내용 |
| --- | --- |
| 제품 | Tap Translate / 탭 번역 |
| 대상 | 작성자 1인. 지금 쓰는 사람은 나뿐이다 |
| 문서 성격 | 제품 기획. 구현 스펙이 아님 |
| 작성일 | 2026-08-22 |
| 상태 | 1차 구현. 기본 꺼짐, 복사만. 기존 [기획서](planning.md) P2 |

관련: [기획서](planning.md), [칩 UX](ux-chip.md)

## 한 줄

페이지는 내가 읽는 언어로 두고, 내가 칸에 쓴 글은 **덮어쓰지 않은 채** 다른 언어로 아래에 보여 준다. 복사만 하면 된다.

## 왜 필요한가

트위터·레딧을 한글로 읽고 싶다. 그런데 그 사이트에 올리는 글은 영어로 쓰는 편이 맞다.

지금은 페이지 번역만 있다. 글을 읽은 뒤 댓글·검색·트윗을 영어로 쓰려면, 머릿속에서 다시 옮기거나 다른 번역 창을 열어야 한다. 읽는 손과 쓰는 손이 갈라진다.

비슷한 확장은 입력칸을 **목표 언어로 바꿔 넣는다.** 원문이 사라지고, 실수하면 실행 취소에 기대야 한다. 나는 내가 쓴 문장을 남긴 채, 영어 초안만 옆에 두고 싶다.

## 지금 기획과의 차이

[기획서](planning.md) P2 초안은 이렇게 적혀 있었다.

- 포커스가 있으면 칩에 “입력 번역”을 붙인다.
- 칸 안의 글을 목표 언어로 **바꿔 넣는다.**
- 페이지와 **같은 목표 언어**를 쓴다.

그 가정은 버린다. 이 기능의 출발은 치환이 아니라 **미리보기**다.

| | 페이지 번역 | 입력 번역 |
| --- | --- | --- |
| 하는 일 | 남이 쓴 글을 내가 읽게 바꾼다 | 내가 쓴 글을 남이 읽게 보여 준다 |
| 목표 언어 | 보는 언어. 예: 한국어 | 쓰는 언어. 예: 영어 |
| 원문 | 칩으로 되돌릴 수 있게 치환 | 칸에 그대로 둔다 |
| 결과물 | 페이지 위 글 | 입력칸 **아래** 미리보기. 복사 가능 |

두 설정은 같이 켜져 있어야 한다. “모든 언어를 한국어로 보고, 내가 쓴 것은 영어로 보고 싶다”가 한 장면이다.

## 원칙

1. **원문을 덮지 않는다.** 입력칸의 값은 내가 소유한다. 번역은 그 아래 별도 표면이다.
2. **설정은 둘이다.** 페이지 목표 언어와 입력 목표 언어를 섞지 않는다.
3. **복사가 본동작이다.** 미리보기를 보고, 필요할 때 복사한다. 칸에 집어넣는 일은 나중이고, 기본이 아니다.
4. **칩을 두 개 만들지 않는다.** 페이지 칩은 읽는 일이다. 입력 미리보기는 지금 포커스된 칸에만 붙는다.
5. **페이지 번역을 깨지 않는다.** 미리보기 DOM은 페이지 번역 대상이 아니다. 비밀번호·코드·OTP 칸은 건드리지 않는다.
6. **탭 한 번을 입력에 억지로 맞추지 않는다.** 입력은 타이핑이 본체다. 번역은 잠시 멈춘 뒤 아래에 나타난다.

## 누구의 어떤 일

| Job | 지금 | 이 기능 |
| --- | --- | --- |
| 영어 피드·스레드를 한글로 읽는다 | 칩 / 항상 번역 | 그대로 |
| 한글로 생각한 댓글·트윗·검색어를 영어로 확인한다 | 없음. 다른 창이거나 포기 | 칸 아래 미리보기 |
| 그 영어를 칸이나 다른 곳에 쓴다 | 없음 | 복사 |
| 내가 쓴 한글을 고친다 | — | 칸은 그대로. 고치면 미리보기만 바뀐다 |

일반화는 미룬다. 첫 장면은 트위터·레딧의 검색창과 글쓰기 칸이다. 메일·이슈·슬랙은 같은 규칙이 통하면 따라온다.

## 장면

설정을 이렇게 둔다.

- 페이지: 한국어로 보기
- 입력: 영어로 보기
- 입력 번역: 켜짐

트위터를 연다. 피드는 한국어다. 검색창에 한글을 넣는다. 칸 아래 영어로 뜬다. 복사해서 검색창에 붙여 넣거나, 한글을 남긴 채 영문만 가져간다.

글쓰기 칸도 같다. 한글로 초안을 적는다. 아래에 영어가 따라온다. 문장을 고치면 미리보기만 갱신된다. 칸의 한글은 지워지지 않는다.

이미 영어인 문장은 미리보기를 열지 않거나, “이미 목표 언어”만 짧게 보여 주고 사라진다.

## 설정

입력 번역은 페이지 번역과 **키를 나눈다.** 기존 `targetLang`은 페이지 전용으로 남긴다.

| 설정 | 하는 일 | 초안 가정 |
| --- | --- | --- |
| 페이지 목표 언어 | 지금 `targetLang`. 페이지를 이 언어로 바꾼다 | 한국어 |
| 입력 목표 언어 | 내가 쓴 글을 이 언어로 보여 준다 | 영어 |
| 입력 번역 켜기 | 꺼두면 칸 아래가 생기지 않는다 | 기본 꺼짐. 켜야 동작 |

꺼진 기본값의 이유: 모든 검색창 아래에 미리보기가 붙으면 페이지 번역보다 시끄럽다. 트위터·레딧을 쓰는 내가 켤 기능이다.

설정 위치는 칩 트레이와 팝업이다. 페이지 언어 바로 아래에 입력 언어를 둔다. “보기 / 쓰기”가 한눈에 갈라져야 한다.

사이트별 입력 언어는 지금 넣지 않는다. 사이트 규칙(기획서 P1)이 먼저다.

## UI

포커스된 쓰기 칸 **아래**에 작은 미리보기 막대가 붙는다.

```
[ 내가 쓰는 칸. 원문 그대로                    ]
[ 영어 미리보기 …                    [복사] ]
```

| 상태 | 아래 |
| --- | --- |
| 꺼짐 / 해당 없는 칸 | 없음 |
| 포커스, 글이 짧음 | 없음 |
| 번역 중 | 이전 결과 유지. 막대만 바쁨 |
| 번역됨 | 목표 언어 문장 + 복사 |
| 이미 목표 언어 | 막대를 닫거나 한 박자 힌트 |
| 실패 | 짧은 실패. 칸은 그대로 |

복사는 미리보기 문장만 클립보드에 넣는다. 성공하면 짧게 “복사됨”.

아래가 화면 밖이거나, 사이트 자동완성이 아래를 쓰는 칸이면 **위로** 붙인다. 트위터 하단 글쓰기, 검색 자동완성이 그 경우다. 기본은 아래, 예외만 위.

페이지 칩과 미리보기는 역할이 다르다. 미리보기가 없을 때 칩에 입력 번역을 얹지 않는다. 칩 트레이는 설정만 한다.

## 어떤 칸을 다루나

다룬다.

- `input[type=text]`, `search`, `url`이 아닌 일반 검색·한 줄 입력
- `textarea`
- `contenteditable` (트위터·레딧 글쓰기)

다루지 않는다.

- `password`, `email`, `tel`, `otp` / one-time-code
- `hidden`, `number`, `file`, 읽기 전용, disabled
- 코드 미러, 터미널, IDE 칸
- 우리 칩·미리보기 자신

애매한 칸(검색 vs 주소, 리치 에디터)은 첫 장면에서 트위터·레딧이 되면 충분하다. 사이트 화이트리스트는 나중에 본다.

## 언제 번역하나

타이핑마다 보내지 않는다. **입력이 잠깐 멈춘 뒤** 지금 칸의 글을 한 덩어리로 보낸다.

이미 목표 언어면 요청하지 않는다. 페이지 번역과 같은 백엔드, 같은 실패 탈출을 쓴다. 목표 언어만 입력 설정을 따른다.

포커스가 다른 칸으로 옮기면 이전 미리보기는 닫힌다. 칸이 사라지면(모달 닫힘) 같이 사라진다.

## 넣지 않는 것

이번 범위에 올리지 않는다.

- 칸 내용을 번역문으로 **치환**하기. 실행 취소로 되돌리는 흐름
- 입력 미리보기와 페이지를 문장 단위로 나란히 보기
- 입력 번역 기록, 용어집
- 사이트마다 다른 입력 목표 언어
- 우클릭 “이 입력 번역”
- 비밀번호·코드 칸을 “예외적으로” 열기

치환은 나중에 열 수 있다. 열더라도 기본이 아니고, 미리보기에서 “칸에 넣기” 한 번이어야 한다. 지금 성공 조건이 아니다.

## 성공을 어떻게 볼 것인가

- 페이지는 한국어, 입력 미리보기는 영어. 두 설정이 서로 덮지 않는다.
- 트위터·레딧 검색창과 글쓰기 칸에서, 한글을 남긴 채 영어가 아래에 뜬다.
- 복사가 한 번이다. 번역문을 드래그해 고를 필요가 없다.
- 미리보기를 켠 뒤에도 페이지 칩의 탭·드래그·원문 복원이 같다.
- 입력 번역을 끄면 칸 아래가 완전히 사라진다.

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 사이트 자동완성·멘션 목록과 아래 미리보기가 겹침 | 기본은 아래, 겹치면 위. 사이트 특수 케이스는 첫 장면에만 손으로 맞춤 |
| contenteditable 글쓰기 칸의 위치·리사이즈 | 칸에 붙고, 칸을 따라간다. 페이지 스크롤에 고정 플로팅을 만들지 않는다 |
| 페이지 번역이 미리보기 글을 다시 한국어로 바꿈 | 미리보기는 Shadow DOM. 페이지 번역이 이미 건너뛰는 입력·위젯과 같은 울타리 |
| 타이핑마다 요청이 나감 | 멈춘 뒤에만 보낸다. 짧은 글은 보내지 않는다 |
| 칩과 미리보기가 두 개의 제품처럼 보임 | 미리보기는 설정 없는 결과물만. 언어 변경은 칩 트레이·팝업 |

## 열린 질문

구현 전에 정하면 좋은 것들이다. 지금은 초안 가정이 있다.

1. **입력 번역 기본값**  
   결정: 꺼둠. 입력 목표 언어는 영어. 페이지 목표 언어는 지금처럼 브라우저 언어.

2. **이미 목표 언어인 입력**  
   가정: 막대를 닫는다. “이미 영어”를 계속 보여 주면 검색창이 시끄럽다.

3. **치환(“칸에 넣기”)**  
   결정: 1차에는 없다. 복사만.

4. **검색 자동완성과의 충돌**  
   가정: 아래가 막히면 위. 사이트별로 미리보기를 끄지 않는다.

5. **우선순위**  
   가정: 기획서 단계는 그대로 2.3 근처다. 다만 이 일은 이제 빈 칸이 아니라, 트위터·레딧에서 매일 쓰는 손에 가깝다. 칩이 편해진 다음이라는 조건은 유지한다.
